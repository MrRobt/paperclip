# CMPAA-126 核心小队提效回归与三闸门验收清单

## 目标

为纸夹二开后的核心小队调度、完成门禁、恢复链去重、噪声评论识别和状态回摆防护建立可执行验收清单。清单覆盖接口测试、前端人工验收和异常场景，供质检、主控和下游复验复用。

## 适用范围

- 公司维度核心小队模式：默认只保留核心成员参与新任务调度。
- 一人一高优：同一成员最多一个高优先级未完成主任务。
- 二十分钟无六件套缩小任务：高优任务长时间无有效完成证据时，应缩小任务或拆分接力。
- 三闸门验收：执行者自验、质检复验、主控终验。
- 恢复链去重：同一源问题只允许一个有效恢复行动，避免恢复任务反复生成。
- 噪声评论识别：运行噪声、重复恢复话术、无证据评论不得被算作完成。
- 状态回摆防护：已完成/取消/已阻塞任务不得被普通代理评论意外拉回待办或进行中。

## 前置条件

1. 仓库位于 `/root/paperclip-work/paperclip`，分支为 `dev`。
2. 本机服务可访问：`http://127.0.0.1:3101`。
3. 所有写入均走纸夹接口，不直接修改数据库。
4. 测试前记录目标公司编号、测试成员编号、测试任务编号；测试数据标题统一带 `CMPAA-126-回归`，便于清理。
5. 若处于认证模式，所有写入请求补充真实代理令牌和真实运行编号请求头。

## 一、接口回归测试

### 1. 健康与公司任务读取

命令：

```sh
curl -s http://127.0.0.1:3101/api/health | python3 -m json.tool
curl -s "http://127.0.0.1:3101/api/companies/<公司编号>/issues?status=backlog" | python3 -m json.tool
```

通过标准：

- 健康接口返回可解析结果。
- 公司任务列表可读取，且不会跨公司泄露任务。

### 2. 一人一高优检查

命令：

```sh
curl -s "http://127.0.0.1:3101/api/companies/<公司编号>/issues?assigneeAgentId=<成员编号>" \
  | python3 -c 'import sys,json; xs=json.load(sys.stdin); ys=[i for i in xs if i.get("priority")=="high" and i.get("status") not in ("done","cancelled")]; print(len(ys)); [print(i["identifier"], i["status"], i["title"]) for i in ys]'
```

通过标准：

- 核心成员同一时间高优未完成主任务数量不超过 1。
- 如超过 1，主控必须转派、降优先级或拆分为阻塞/接力关系。

### 3. 六件套完成评论校验

准备一个候选完成评论，必须包含：改动摘要、分支、提交号、验证命令、验证结果、下游复验口径。

命令：

```sh
curl -s "http://127.0.0.1:3101/api/issues/<任务编号>/comments?order=desc&limit=10" \
  | python3 -c 'import sys,json,re; comments=json.load(sys.stdin); keys=["改动摘要","分支","提交号","验证命令","验证结果","下游复验口径"]; body="\n".join(c.get("body","") for c in comments); missing=[k for k in keys if k not in body]; print("通过" if not missing else "缺失:"+",".join(missing))'
```

通过标准：

- 进入完成候选前，最近有效完成评论必须包含六件套。
- 只包含“已完成”“已修复”“继续推进”等短句的评论不得算完成证据。

### 4. 二十分钟无六件套缩小任务

命令：

```sh
curl -s "http://127.0.0.1:3101/api/issues/<任务编号>" | python3 -m json.tool
curl -s "http://127.0.0.1:3101/api/issues/<任务编号>/comments?order=desc&limit=20" | python3 -m json.tool
```

通过标准：

- 高优任务进行中超过二十分钟且无六件套时，任务评论应出现缩小范围、拆分子任务或明确阻塞说明之一。
- 不允许恢复链反复唤醒但没有新的验收证据。

### 5. 三闸门验收状态流

推荐流转：

```text
执行者完成并留六件套 -> 质检复验通过 -> 主控终验 -> done
执行者完成但证据不足 -> 质检退回 todo/in_progress 并说明缺口
质检发现阻塞 -> 标记 blocked 并挂明确阻塞项
```

命令：

```sh
curl -s "http://127.0.0.1:3101/api/issues/<任务编号>" | python3 -c 'import sys,json; i=json.load(sys.stdin); print(i.get("status"), i.get("assigneeAgentId"), i.get("productivityReview"), i.get("executionState"))'
```

通过标准：

- 没有复验证据的任务不得直接终验完成。
- 退回必须带缺口说明，不允许只改状态。
- 终验完成必须能追溯到执行者、质检、主控三段证据。

### 6. 恢复链去重

命令：

```sh
curl -s "http://127.0.0.1:3101/api/issues/<任务编号>" | python3 -c 'import sys,json; i=json.load(sys.stdin); print(json.dumps({"blockerAttention": i.get("blockerAttention"), "relatedWork": i.get("relatedWork"), "referencedIssueIdentifiers": i.get("referencedIssueIdentifiers")}, ensure_ascii=False, indent=2))'
```

通过标准：

- 同一源任务只存在一个有效恢复行动或一个明确阻塞项。
- 重复标题、重复来源指纹、重复恢复评论应被合并或忽略。
- 恢复任务不应彼此循环阻塞。

### 7. 状态回摆防护

命令：

```sh
curl -s -X POST "http://127.0.0.1:3101/api/issues/<已完成任务编号>/comments" \
  -H "Content-Type: application/json" \
  -d '{"body":"CMPAA-126-回归：普通代理补充说明，不请求恢复。"}' \
  | python3 -m json.tool
curl -s "http://127.0.0.1:3101/api/issues/<已完成任务编号>" | python3 -c 'import sys,json; print(json.load(sys.stdin)["status"])'
```

通过标准：

- 普通代理评论已完成任务后，状态仍为 `done`。
- 只有带明确恢复意图且有权限的请求，才允许把关闭任务转回待办。

## 二、前端人工验收步骤

### 1. 仪表盘总览

路径：`http://127.0.0.1:3101/<公司标识>/dashboard`

检查项：

- 核心小队成员清晰可见，非核心成员不应被误展示为默认执行队列。
- 高优任务分布能看出“一人一高优”是否被破坏。
- 运行中、阻塞、待质检、完成的数量与接口返回一致。
- 页面刷新后状态不跳变、不重复出现恢复任务。

### 2. 任务列表页

路径：`http://127.0.0.1:3101/<公司标识>/issues`

检查项：

- 按负责人过滤时，只看到该成员任务。
- 按状态过滤时，完成/取消任务不会混入未完成队列。
- 高优任务、阻塞任务、待复验任务有明显标识。
- 噪声评论不会让任务卡片显示为“已完成”。

### 3. 任务详情页

检查项：

- 六件套评论可直接阅读，不需要翻原始运行日志才能确认结果。
- 三闸门证据链可追溯：执行者自验、质检复验、主控终验。
- 阻塞原因、恢复行动、关联任务展示一致。
- 对已完成任务新增普通评论后，页面状态不回摆。

### 4. 异常体验

检查项：

- 服务重启后，页面恢复加载且不新增重复恢复项。
- 接口返回失败时，前端显示明确错误，不吞掉失败。
- 大量评论任务仍能打开，完成证据靠前或可定位。

## 三、异常场景矩阵

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 重复恢复 | 对同一阻塞源连续触发恢复预览/运行 | 只保留一个有效恢复行动或明确去重提示 |
| 噪声完成 | 只评论“完成了”并尝试收尾 | 不通过质检，必须补六件套 |
| 超时无证据 | 高优任务二十分钟无六件套 | 缩小任务、拆子任务或明确阻塞，不允许空转 |
| 多高优压人 | 同一成员出现两个高优未完成任务 | 主控调度纠偏，保留一个主任务，其余降级/转派/阻塞 |
| 已完成补充评论 | 对已完成任务发普通说明 | 状态保持完成，不回摆 |
| 取消任务补充评论 | 对取消任务发普通说明 | 状态保持取消，不回摆 |
| 阻塞未解除恢复 | 阻塞项仍未解决时请求恢复 | 返回冲突或继续阻塞，不进入待办 |
| 前端刷新 | 仪表盘和任务页连续刷新 | 统计稳定，不重复创建恢复任务 |

## 四、下游复验口径

下游质检按以下顺序复验：

1. 先跑健康和任务读取接口，确认服务可用。
2. 随机抽取 3 个核心成员，检查“一人一高优”。
3. 抽取最近 5 个完成任务，检查六件套和三闸门证据。
4. 抽取最近 3 个阻塞/恢复任务，检查恢复链是否去重。
5. 在前端分别查看仪表盘、任务列表、任务详情，确认状态和接口一致。
6. 用一个已完成测试任务补充普通评论，确认状态不回摆。
