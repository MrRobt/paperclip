# 2026-06-06 纸夹 DYQ 运行复盘：不好用点、止血状态与手动派单产品逻辑

## 1. 结论

纸夹在 DYQ 场景中的核心问题不是“代理数量不足”或“模型不够聪明”，而是自动调度边界过宽：定时心跳、主控巡检、并发闸门、恢复链、生产力审查、智能模型巡检同时运行，把看板系统用成了自动心跳空转机器。

当前产品方向调整为：

> 纸夹保留为看板、任务、评论、运行、产物和成本记录系统；真实执行改为小黑手动派单，原生赫尔墨斯子代理按明确工单短程执行，完成后必须回填可验收证据。

## 5. 新的 DYQ 使用原则

### 5.1 总原则

1. 禁止全员自动心跳。
2. 只允许小黑主控手动派单。
3. 每次只唤醒一个明确工单和一个明确成员。
4. 工单必须包含仓库路径、分支、文件范围、验收命令、回填要求。
5. 阻塞态工单不能自动唤醒执行成员。
6. 恢复工单和生产力审查只做看板记录，不自动执行。
7. 没有验收口径，不允许派单。
8. 没有交付证据，不允许关闭。

### 5.2 手动派单六件套

每次小黑派单必须写清：

```text
1. 仓库路径：
2. 分支：
3. 允许文件范围：
4. 禁止文件范围：
5. 验收命令：
6. 完成回填要求：提交号、验证日志、截图或产物、未完成项
```

缺任一关键字段，不唤醒成员。

### 5.3 成员完成六件套

成员完成时必须回填：

```text
1. 改动摘要：
2. 分支：
3. 提交号：
4. 实际修改文件：
5. 验证命令与结果：
6. 下游复验口径：
```

没有提交号或验证日志，不进入已完成。

## 6. 产品状态机设计

### 6.1 工单状态机

```text
草稿
  ↓ 小黑补齐派单六件套
待派单
  ↓ 小黑指定唯一成员
已派单
  ↓ 小黑手动唤醒
执行中
  ↓ 成员完成并回填证据
待验收
  ↓ 验收通过
已完成
```

异常分支：

```text
执行中 → 阻塞待裁决 → 小黑补上下文/拆分/重派 → 待派单
执行中 → 失败待裁决 → 小黑重派/取消/人工接管
待验收 → 验收不通过 → 返修待派单
```

### 6.2 阻塞状态规则

- 阻塞态不是执行态。
- 阻塞态不允许系统自动唤醒执行成员。
- 阻塞态必须有阻塞原因和解除条件。
- 解除阻塞后必须重新派单，不复用旧运行。

### 6.3 恢复建议状态机

```text
异常发现
  ↓
恢复建议
  ↓ 小黑裁决
忽略 / 合并记录 / 创建新工单 / 手动派单
```

恢复建议不是执行工单，不能直接唤醒成员。

## 7. 原生赫尔墨斯子代理迭代规则

后续不用纸夹自动心跳驱动开发，改用原生赫尔墨斯子代理短程并行。

### 7.1 默认协作流

```text
小黑主控
  ↓ 拆成一到三个明确小任务
原生赫尔墨斯子代理只读分析或小范围执行
  ↓ 输出证据/文档/补丁
小黑自审与整合
  ↓ 必要时再进入下一批
```

### 7.2 子代理任务粒度

允许派发：

- 单文件或小范围代码改动；
- 单个接口、单个组件、单个测试模块；
- 单篇文档增量更新；
- 单个缺陷根因分析；
- 单个验收清单执行。

禁止派发：

- “全面优化纸夹”；
- “把团队调度做好”；
- “自己找问题长期跑”；
- “无边界巡检全部代码”。

### 7.3 批次节奏

```text
批次 N：
1. 小黑创建一到三个明确任务；
2. 原生赫尔墨斯子代理并行分析或执行；
3. 小黑整合产出；
4. 跑最小验证；
5. 决定是否进入批次 N+1。
```

每批必须短程、可回滚、可验收。

## 8. 技术改造优先级

### 8.1 先止血

1. 调度开关和降频。
   - 入口：`server/src/index.ts`
   - 目标：避免自动恢复、自动审查、自动巡检每轮都产生副作用。

2. 恢复/审查来源统一防递归。
   - 入口：`server/src/services/recovery/origins.ts`
   - 目标：恢复工单、审查工单、活跃运行评估不互相繁殖。

3. 生产力审查不自动唤醒。
   - 入口：`server/src/services/productivity-review.ts`
   - 目标：审查只落板，由小黑裁决。

4. 阻塞工单唤醒闸门收紧。
   - 入口：`server/src/services/heartbeat.ts`
   - 目标：系统自动唤醒不能绕过依赖阻塞。

5. 适配器配置校验。
   - 入口：`server/src/adapters/registry.ts`
   - 目标：启动前拦截错误命令、错误模型、错误工作区。

### 8.2 再做产品化

1. 公司级“主控模式”开关。
2. 手动派单表单强制六件套。
3. 恢复建议页和生产力审查页只读化。
4. 工作区绑定必填，缺失时快速失败。
5. 原生赫尔墨斯瘦身任务包。
6. 运行成本与有效产出看板。

## 9. 恢复自动化前验收清单

任何纸夹自动化恢复前，必须满足：

- [ ] 有主控批准。
- [ ] 有本轮任务清单。
- [ ] 有唯一成员与唯一工单映射。
- [ ] 有仓库路径、分支、文件范围、验收命令。
- [ ] 有预计预算与最大运行时长。
- [ ] 有最大并发，初期必须为一。
- [ ] 有 live-runs 批量取消入口。
- [ ] 有恢复链去重与冷却策略。
- [ ] 有生产力审查只提醒、不自动唤醒配置。
- [ ] 有阻塞态自动唤醒拦截。
- [ ] 有完成六件套检查。
- [ ] 有前端真实浏览器验收口径。

不满足以上清单，不恢复 cron，不恢复全员心跳。

## 10. 后续开发批次建议

### 批次一：只读诊断与主控模式设计

目标：先看清楚，不自动干预。

- 新增公司级主控模式设计；
- 新增只读团队健康页；
- 展示 active runs、blocked issues、恢复建议、成本异常；
- 不新增任何自动唤醒。

### 批次二：人工门禁

目标：系统提醒，小黑确认。

- 手动派单表单强制六件套；
- 唤醒前预览；
- 阻塞态禁止自动唤醒；
- 恢复建议转工单需人工确认。

### 批次三：小规模条件唤醒

目标：谨慎恢复局部自动化。

- 单 cron；
- 单并发；
- 只处理无阻塞、信息完整、验收明确的工单；
- 超时、失败、无证据立即停。
