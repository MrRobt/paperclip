# 需求与边界

## 需求

围绕目标池持续自主迭代，逐步完成所有目标和问题，形成云端中枢、端侧执行体、微信托管智能体和自动化赚钱场景的商业化闭环。

## 强制规则

- 每轮必须先读相关仓库上下文文件，优先 `.claude/CLAUDE.md` 和 `.claude/rules`。
- 禁止空巡检；每轮必须推进一个最小可验证动作。
- 默认测试先行；不能写自动化测试时，必须写可执行验证脚本或接口冒烟。
- 前端问题必须尽量用真实浏览器验证。
- 后端主服务默认 dyq-server:48080；启动新 Java 进程前必须先停旧 Java 进程。
- 不强推、不删除远端修改、不泄露密钥、不做真实资金动作、不做生产数据删除。

## 暂不做

- 未经主人明确授权，不进行真实资金交易、生产数据批量删除、大规模外呼或大规模真实用户触达。
- 不引入破坏现有架构边界的大重构；重大架构变更先写设计。
