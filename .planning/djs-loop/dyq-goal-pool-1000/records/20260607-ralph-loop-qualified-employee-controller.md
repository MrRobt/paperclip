## 新主控行为变化

### 旧问题

- 主要做巡检、评论、矩阵、看板流转。
- 允许无提交号的完成。
- 任务标题扩出 C3/P3/W3/WEB3，容易偏离原目标树。
- worker 阻塞后没有立即强收口或重派。

### 新规则

- 每轮必须主动推进一个最小功能闭环。
- 优先收口已有功能差异，不再先扩新任务。
- 没有提交号的 done 必须打回或补收口。
- 新卡标题必须映射原目标树节点，例如 `P2.1`、`S1.1`。
- 主控可以在安全范围内亲自运行验证、整理证据、提交已有功能差异。
- 如果某目标强阻塞，必须记录阻塞并转向另一个可推进目标。

## 当前优先级

1. PokeClaw：已有端侧脚本但无提交，必须验证并提交，映射 P1/P2。
2. 管理后台：WEB 卡已阻塞，已有页面/API/路由改动，必须重派或亲自构建验证后提交，映射 S/C/P/W 管理入口。
3. 后端与 WeFlow：已有提交，主控只复核，不重复造轮子。
4. QC：只有 PokeClaw 和 Web 都有提交后才启动。

## 新完成定义

任何完成必须同时包含：

- 原目标树节点映射；
- 真实代码/接口/页面/脚本改动；
- 本地提交号，或明确不能提交的阻塞原因和差异证据；
- 验证命令与结果；
- 证据目录；
- 下一轮最小功能点。
