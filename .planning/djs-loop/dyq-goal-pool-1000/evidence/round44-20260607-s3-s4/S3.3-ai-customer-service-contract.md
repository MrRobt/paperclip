## 1. 目标与验收口径

**目标树原文**：落点：dyq-module-cs 与前端客服页面。验收：客服会话能展示 AI 建议、人工接管、满意度、未读提醒；WeFlow 微信消息可进入 CS 会话。

**本草案交付的最小契约**：

| 接口方法 | 入参 | 出参 | 验收口径覆盖 |
|---|---|---|---|
| `pushMessage` | `AiCustomerServiceMessageDTO` | `CommonResult<AiCustomerServiceMessageDTO>` | 客户/AI/坐席三源消息统一入库 |
| `listRecentMessages` | sessionId, limit | `CommonResult<List<...>>` | 客服工作台展示会话消息 |
| `generateSuggestion` | sessionId, triggerMessageId | `CommonResult<AiSuggestionDTO>` | AI 建议 |
| `takeoverByHuman` / `releaseTakeover` | `HumanTakeoverReqDTO` / sessionId, agentId | `CommonResult<Boolean>` | 人工接管 |
| `submitSatisfaction` | sessionId, score | `CommonResult<Boolean>` | 满意度 |
| `ingestWechatMessage` | wechatMessageId, sessionId | `CommonResult<AiCustomerServiceMessageDTO>` | WeFlow 微信消息进入 CS 会话 |

未读提醒由 message DTO 的 `readFlag` + `reminderSent` 字段承担，前端轮询或主动推；事件化由后续轮次补。

## 2. 消息源与字段归一化

| 字段 | 取值 | 说明 |
|---|---|---|
| `source` | AI / AGENT / CUSTOMER / WEFLOW | 消息来源 |
| `messageType` | TEXT / IMAGE / SYSTEM / SUGGESTION | 消息类型，SUGGESTION 表示 AI 建议已落库 |
| `senderId` | customerId / agentId / aiModel / deviceId | 发送方标识 |
| `satisfactionScore` | 1-5 / 0=未评分 | 客户评分 |
| `wechatMessageId` | 微信侧 ID | WeFlow 来源时回填，便于端云对账 |

## 3. 安全边界（主人定调：默认人工确认）

- 所有外部发送保持 `requiresHumanConfirmation=true / sendActionExecuted=false / externalActionAllowed=false`。
- AI 建议只生成不发送；`takeoverByHuman` 接管期间暂停 AI 主动建议但仍生成草稿；解除后恢复草稿模式。
- WeFlow → CS 消息接入走 `ingestWechatMessage`，但 CS 侧若回写微信仍走 WeFlow 已验证的安全草稿通道（W2.1 边界）。
