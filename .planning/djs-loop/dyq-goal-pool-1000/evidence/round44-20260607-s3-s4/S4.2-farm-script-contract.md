## 2. 云端契约（草案）

### 2.1 脚本模板（云端存）

```
FarmScriptTemplate
  ├─ id
  ├─ name                  // 模板名：标准养号-新号7日 / 高活跃冲刺 等
  ├─ platform              // XIAOHONGSHU / DOUYIN / ...
  ├─ actionSequence[]      // 动作序列：[{type, weight, minMs, maxMs, count}]
  ├─ dailyQuota            // 每日配额（防刷）
  ├─ riskGuard             // 风险守卫：触发后自动降级或暂停
  └─ version               // 模板版本（灰度用）
```

动作类型枚举（与 PokeClaw 端侧实现对齐）：
- `BROWSE_FEED` 浏览首页 / 同城 / 关注流
- `BROWSE_DETAIL` 浏览指定作者/笔记/视频详情
- `LIKE` 点赞（权重低于 BROWSE，避免触发风控）
- `COMMENT` 评论（要求 requiresHumanConfirmation=true）
- `FOLLOW` 关注
- `STAY` 停留指定时长
- `RANDOM_WAIT` 随机等待（人类节奏）

### 2.2 任务下发（云端 → PokeClaw 端侧）

复用 `ClawDeviceApi.createDeviceTask(ClawDeviceTaskDTO)`，扩展 `command` 字段：
- `command=farm.script.run`
- `mode=TEMPLATE` 携带 `scriptTemplateId` + `version`
- `priority=LOW`（默认低优先级，避免与业务任务抢资源）

云端侧新接口（草案）：
- `listFarmScriptTemplates(platform)`：按平台查可用模板
- `getFarmScriptTemplate(id, version)`：查单个模板
- `createFarmTask(accountUid, scriptTemplateId, version, dailyQuota)`：把脚本任务落到账号

### 2.3 执行日志回传（端侧 → 云端）

复用 `ClawDeviceApi.updateTaskStatus(taskUuid, status, result)`，约定 `status` 取值：
- `RUNNING`：动作序列开始
- `PARTIAL`：单动作完成（携带 `evidenceUrls` 截图）
- `SUCCESS`：全序列完成
- `FAILED`：单动作失败（携带 `errorMessage`）

`result` 字段为 JSON 字符串，包含：
```
{
  "scriptTemplateId": "...",
  "actions": [
    {"type": "BROWSE_FEED", "ok": true, "durationMs": 12345, "evidenceUrl": "..."},
    ...
  ],
  "totalDurationMs": 600000,
  "humanLikeScore": 0.87
}
```

云端聚合接口（草案）：
- `getAccountFarmLogs(accountUid, sinceDays)`：拉账号最近 N 天养号日志
- `getPlatformFarmStats(platform, sinceDays)`：按平台聚合统计

### 2.4 安全边界

- 全部动作序列默认 `requiresHumanConfirmation=true`，仅 `BROWSE` / `STAY` / `RANDOM_WAIT` / `LIKE` 可在主人授权下走 `externalActionAllowed=true` 通道。
- `COMMENT` / `FOLLOW` 必须人工确认（与 S2.2 社媒草稿闭环一致）。
- `dailyQuota` 与 `riskGuard` 由云端强制，端侧不得擅自突破。
- 执行日志必须带设备 ID、账号 UID、平台，便于事后审计与回溯。
