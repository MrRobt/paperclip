# 纸夹智能体交付系统完整实施计划

状态：进行中

## 总体策略

本计划不是最小化实现，而是完整研发实现。执行方式采用 djs-loop：计划先行、泳道并发、泳道内串行、集成串行、主控验收。

   - 文件：`packages/db/src/schema/issue_blocker_policies.ts`

## 里程碑二：服务端核心服务

目标：打通诊断、草稿、阻塞、模型健康、证据闸门五个核心服务。

任务：

1. 诊断聚合服务。
   - 文件：`server/src/services/control-plane-diagnostic.ts`
   - 测试：健康、可疑、阻塞、静默停滞四类判定。

2. 评论草稿服务。
   - 文件：`server/src/services/issue-comment-drafts.ts`
   - 接入：现有 `comment-draft-queue.ts`
   - 测试：保存、查询、重放成功、重放失败、幂等处理。

3. 阻塞策略服务。
   - 文件：`server/src/services/issue-blocker-policies.ts`
   - 测试：强阻塞禁止执行但允许补证据；弱阻塞允许补证据；提示阻塞只提示。

4. 模型健康服务。
   - 文件：`server/src/services/model-health.ts`
   - 文件：`server/src/services/model-fallback-policy.ts`
   - 测试：失败率聚合、降级建议、预算约束。

5. 证据闸门扩展。
   - 文件：`server/src/services/dispatch-gates.ts`
   - 测试：完成证据完整、证据不足、无提交原因、验证失败。

验收：

- 服务端相关单元测试通过。
- 服务不破坏现有心跳和恢复流程。
- 所有服务输出可被接口层直接使用。

## 里程碑四：心跳、恢复与后台任务接入

目标：让系统在运行过程中自动产生诊断和恢复动作。

任务：

1. 心跳接入评论草稿。
   - 文件：`server/src/services/heartbeat.ts`
   - 评论失败保存草稿。
   - 心跳结果写模型健康事件。

2. 恢复服务接入诊断。
   - 文件：`server/src/services/recovery/service.ts`
   - 静默停滞生成恢复动作。
   - 唤醒跳过写明确原因和建议动作。

3. 本地诊断服务升级。
   - 文件：`server/src/services/local-ops-diagnostic.ts`
   - 与控制面诊断聚合对齐。

4. 后台调度。
   - 周期生成诊断快照。
   - 周期尝试安全草稿重放。
   - 周期刷新模型健康。

验收：

- 模拟心跳评论失败能生成草稿。
- 模拟运行静默能生成恢复动作。
- 模拟模型失败能生成健康事件和降级建议。

## 并行分工建议

| 泳道 | 类型 | 任务 | 文件边界 |
|---|---|---|---|
| 数据库泳道 | 串行锁 | 新表、迁移、导出 | `packages/db/` |
| 服务端诊断泳道 | 可并发 | 诊断、证据闸门、恢复接入 | `server/src/services/` |
| 接口泳道 | 依赖服务后串行 | 路由、接口文档、错误处理 | `server/src/routes/` |
| 前端泳道 | 接口契约定稿后并发 | 页面、客户端、路由、导航 | `ui/` |
| 测试泳道 | 可并发 | 单测、路由测试、页面冒烟 | `server/src/**/*.test.ts`、`ui/` |
| 集成泳道 | 串行 | 全量门禁、冲突处理、提交 | 全仓库 |
