# 纸夹智能体交付系统完整研发目标

启动时间：2026-06-08 11:03:30 +0800
状态：进行中

## 主人原始目标

基于已整理的纸夹服务阻塞自愈方案，使用 djs-loop 方式输出完整实时方案计划；不要最小化实现，要完整实现智能体交付系统的功能研发实现。

## 工程化目标

把纸夹从“智能体事项看板”升级为“智能体交付系统”：

1. 能实时看清每个智能体、事项、运行、评论、证据、阻塞、恢复动作的健康状态。
2. 评论失败不丢失，失败评论进入可重放草稿队列。
3. 阻塞不再一刀切，支持强阻塞、弱阻塞、提示阻塞，并允许补评论、补证据、补诊断。
4. 智能体运行静默、模型通道异常、适配器异常、预算硬停、工作区异常时，系统能生成明确恢复动作。
5. 完成事项必须绑定可审计证据，不能只靠智能体自报完成。
6. 管理端提供实时交付控制台，可批量唤醒、重放评论、执行恢复、查看健康分布和风险队列。
7. 所有改造遵守纸夹既有公司作用域、单负责人事项、原子领取、审批闸门、预算硬停、活动日志等控制面不变量。

## 已读取项目上下文摘要

- 仓库：`/root/paperclip-work/paperclip`
- 分支：`dev`

- 服务端：`server/`，接口与编排服务。
- 前端：`ui/`，看板操作界面。

- 核心规则：所有业务记录必须有公司作用域；改接口或表结构时必须同步数据库、共享类型、服务端和前端；所有写操作必须有活动日志；完成前需要类型检查、测试和构建。
- 当前工作区已有大量历史未提交文件，本目标只纳入本目录和后续明确切片产生的改动；不清理、不重置、不删除未知历史文件。

## 红线

1. 不强推远端。
2. 不删除远端修改或未知历史文件。
3. 不泄露密钥。
4. 不绕过审批、预算硬停和公司作用域约束。
5. 不把真实外部触达做成自动执行；真实触达仍需人工确认。
6. 重大架构变更先设计后实施。

## 完成口径

本目标完成需要同时满足：

- 全量方案、需求、设计、实施计划、验收清单已落地。
- 后续代码实施按计划推进，每个阶段有测试、接口、页面或日志证据。
- 新增接口、数据表、前端页面、后台任务和活动日志闭环。
- 质量门禁通过或清楚记录未通过原因。
- 工作区改动范围可解释。
